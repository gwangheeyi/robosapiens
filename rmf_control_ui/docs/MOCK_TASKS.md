# Pinky · OMX-AI 연속 작업 가이드

## 개요

`작업` 메뉴에서는 Pinky 주행과 OMX-AI 로봇팔 동작을 하나의 연속 작업으로
작성할 수 있습니다. 각 단계는 앞 단계가 정상 완료된 뒤에만 시작합니다.

```text
Pinky → 픽업3 이동
    ↓ 도착
OMX-AI → 화물 픽업 후 Pinky 데크에 적재
    ↓ 적재 완료
Pinky → 대기1 이동
```

## 사용 순서

1. 로봇 메뉴에서 배포 맵을 불러옵니다.
2. 시작 Waypoint를 선택해 Pinky 로봇을 Spawn합니다.
3. 작업 메뉴에서 `새 작업`을 누릅니다.
4. Pinky를 자동 또는 직접 배정합니다.
5. `단계 추가`로 실행 단계를 작성합니다.
6. 카드를 드래그해 순서를 바꾸거나 휴지통 버튼으로 삭제합니다.
7. `연속 작업 시작`을 누르고 목록에서 단계 진행률을 확인합니다.

## 지원 단계

| 단계 | 실행 내용 |
| --- | --- |
| Pinky 이동 | 선택한 Waypoint까지 Lane 최단 경로로 이동 |
| OMX-AI 픽업 | 현재 위치의 화물을 집어 Pinky 데크에 적재 |
| 대기 | 선택한 시간 동안 다음 단계를 시작하지 않음 |

편집기는 기본 예제로 `Pinky 이동 → OMX-AI 픽업 → Pinky 이동` 세 단계를
만듭니다. 첫 이동 목적지를 `픽업3`, 마지막 이동 목적지를 `대기1`로 바꾸면
요청한 작업이 완성됩니다.

## 실행과 실패 처리

- 이동 단계는 현재 Lane 방향을 반영해 최단 경로를 다시 계산합니다.
- 목적지까지 갈 수 없으면 해당 단계와 전체 작업을 `실패` 처리합니다.
- OMX-AI 단계는 팔 동작이 끝나야 다음 단계를 시작합니다.
- 진행 중 작업을 취소하면 활성 단계와 나머지 단계가 취소되고 Pinky가 멈춥니다.
- 로봇을 제거하면 그 로봇의 진행 중 작업은 실패합니다.

## 실제 장비 연결 경계

현재 `rmf_control_ui` 화면의 실행은 앱 내부 로봇에서 확인하는 실행 모델입니다.
실제 장비 명령 형식은 기존 `robo_pinky_agent`와 동일하게 설계되어 있습니다.

- Pinky: 관제에서 `path`(Waypoint 배열) 전송
- OMX-AI: 관제에서 `load` 전송
- OMX-AI 완료: `loaded` 수신
- OMX-AI 실패: `loadFailed`와 사유 수신
- 취소: `abort` 전송

실제 Pinky와 OMX-AI를 움직이려면 로컬 Linux의 장비 게이트웨이(TCP 8788)와
Fleet Adapter가 실행 중이어야 합니다. 웹 브라우저가 로봇에 직접 명령하지 않고,
로컬 Edge Agent가 명령 전달과 안전 정지를 담당해야 합니다.

## 현재 제한사항

- 작업과 이력은 앱 메모리에만 있으며 앱 종료 시 사라집니다.
- 이 UI 자체에서는 아직 TCP 8788로 실제 명령을 보내지 않습니다.
- 여러 Pinky 사이의 Lane 예약과 충돌 회피는 RMF 연동 후 적용해야 합니다.
- 실제 OMX-AI 완료는 고정 시간이 아니라 `loaded` 응답으로 판정해야 합니다.
