왜 토픽이 안 왔나
브링업은 정상이었습니다. 문제는 이 무선 AP 가 멀티캐스트를 막는 것이었습니다.

측정한 결과입니다:

시험	결과
로봇 → PC 유니캐스트	통함
로봇 → PC 멀티캐스트	막힘
PC → 로봇 멀티캐스트	막힘

DDS 디스커버리는 기본이 멀티캐스트입니다. 그게 막히니 양쪽 다 멀쩡히 돌면서도 서로를 영영 못 찾습니다. 오류가 하나도 안 나서 라이다나 네임스페이스를 의심하게 되는 유형입니다.

로봇 쪽은 완전히 정상이었습니다 — 로봇 로컬에서 보면 11개 토픽이 다 나오고, odom 30 Hz, scan 10 Hz 로 발행 중입니다. 네임스페이스도 /pinky_02, 도메인도 12로 정확합니다.

해결
ROS_STATIC_PEERS 로 디스커버리를 유니캐스트로 돌렸습니다. 유니캐스트는 통하니까요.

적용 후 관제 PC에서 확인한 결과:


/pinky_02/scan   → 10.05 Hz  수신
/pinky_02/odom   → 29.92 Hz  수신
그 외 11개 토픽 전부 도달
터미널에서 바로 쓰시려면:


export ROS_DOMAIN_ID=12
export ROS_STATIC_PEERS="192.168.0.22"
로봇 쪽에는 ~/.bashrc 에 넣었지만 위에 적은 따옴표 문제가 있으니 고쳐 주세요.

1. 무선 어댑터 2개가 같은 망에 있습니다

ssh 정보를 로컬에 저장하기

1. 공개키를 pinky_01 에 올리기
ssh-copy-id 는 비밀번호를 한 번 물으므로 터미널에서 직접 치셔야 합니다. 앱은 못 합니다.


ssh-copy-id -i ~/.ssh/id_ed25519.pub pinky@192.168.0.21
계정이 pinky 가 맞는지 확인이 필요합니다. pinky_02 의 bringup.service 가 워크스페이스를 ~/pinky_pro 로 쓰는 걸 보면 로봇 계정 홈 아래인데, 계정 이름 자체는 파일에 안 남아 있습니다.

2. BatchMode 로 되는지 확인
앱과 똑같은 조건으로 시험해야 의미가 있습니다. 그냥 ssh 로 되는 건 증명이 안 됩니다 — 비밀번호를 물어서 통과했을 수 있으니까요.


ssh -o BatchMode=yes -o ConnectTimeout=8 pinky@192.168.0.21 'echo OK'
OK 가 나와야 앱도 붙습니다.

3. ~/.ssh/config 는 안 만드셔도 됩니다
앱이 -p, BatchMode, StrictHostKeyChecking 을 명령줄로 직접 넘기고, 주소는 등록에서 user@host 를 만들어 씁니다. config 파일을 안 읽어도 동작합니다. 손으로 ssh pinky01 처럼 짧게 치고 싶으실 때만 편의로 두는 겁니다.

4. known_hosts 도 미리 넣을 필요 없습니다
StrictHostKeyChecking=accept-new 라 처음 보는 로봇 키를 자동으로 받습니다.

주의할 점 하나
buildRobotServiceInstallCommand 는 sudo 를 씁니다 — 부팅 자동 시작(systemd 유닛 설치)을 앱에서 하실 거라면, 로봇 계정에 비밀번호 없는 sudo 가 필요합니다. robot_ssh_io.dart:88 주석에도 "비밀번호를 물으면 BatchMode 때문에 바로 끝난다" 고 적혀 있습니다. 로봇에서:


echo "pinky ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/robosapiens
SSH 브링업 버튼만 쓰실 거면 이건 필요 없습니다 — sudo 는 서비스 설치에만 씁니다.

192.168.0.21 이 pinky_01 이 맞는지, 계정 이름이 무엇인지 확인되면 1~2번을 바로 짚어드리겠습니다. 참고로 pinky.txt 에 적힌 static peer 는 192.168.0.22 인데, 이게 pinky_02 주소인지 확인해두시면 두 로봇 주소가 정리됩니다.
